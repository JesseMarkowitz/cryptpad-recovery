The expected plaintext files are under `fixtures/expected/`. Each Code document was
created as an owned Code pad, explicitly stored in the account's CryptDrive,
allowed to reach the client-side `Saved` state, then reopened from a fresh
CryptDrive page. The reopened editor text matched the byte counts and SHA-256
values above.

Several empty, unreferenced pad channels were also generated while learning the
historical UI's two-stage Create/Store flow. They are not visible in the
CryptDrive. This is useful evidence that datastore inventory alone is not the
logical file inventory; recovery should follow capabilities from the decrypted
drive.

The binary fixture was generated by `fixtures/generate-binary-fixture.js` and
uploaded as an owned CryptPad file. Its size spans three 128 KiB plaintext blob
chunks, exercising metadata decryption, nonce increments, full chunks, and a
short final chunk.
