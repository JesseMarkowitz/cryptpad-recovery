The expected plaintext files are under `fixtures/expected/`. Each Code document was
created as an owned Code pad, explicitly stored in the account's CryptDrive,
allowed to reach the client-side `Saved` state, then reopened from a fresh
CryptDrive page. The reopened editor text matched the byte counts and SHA-256
values above.

Several empty, unreferenced pad channels were also generated while learning the
historical UI's two-stage Create/Store flow. They are not visible in the
CryptDrive. This is useful evidence that datastore inventory alone is not the
logical file inventory; recovery should follow capabilities from the decrypted
drive.

The binary fixture was generated by `fixtures/generate-binary-fixture.js` and
uploaded as an owned CryptPad file. Its size spans three 128 KiB plaintext blob
chunks, exercising metadata decryption, nonce increments, full chunks, and a
short final chunk.

## Phase 6 application fixtures

On 2026-08-29, `scripts/create-phase6-fixtures.js` used the normal browser UI
to create and explicitly store four additional documents:

- Pad `recovery-canary-rich-text-phase6`, containing headings, bold and italic
  spans, a list, and Unicode text;
- Slide `recovery-canary-slides`, containing two Markdown slides and Unicode;
- Kanban `recovery-canary-kanban`, containing the board marker
  `RECOVERY-FIXTURE-BOARD` and card marker
  `RECOVERY-FIXTURE-CARD café 漢字 🚀`; and
- Sheet `recovery-canary-sheet`, with a real OnlyOffice cell edit.

An empty stored Pad named `recovery-canary-rich-text` is retained as an empty
document control. Failed pre-store UI experiments also left unreferenced
encrypted channels, reinforcing that tests must enumerate the decrypted drive
rather than treating every datastore file as user-visible content.

The Phase 6 regression verifies the Pad and Slide exports byte-for-byte,
checks the Kanban structure semantically, and verifies every cryptographic
record in both the Sheet's primary ChainPad history and its secondary
OnlyOffice history. The OnlyOffice change payload is deliberately treated as
opaque: the test proves authenticated preservation, not native `.xlsx`
rendering.
